# 실 데이터 연결 검토

작성일: 2026-09-10

## 결론

**연결 가능하다. 단, 브리지 프로세스가 반드시 하나 필요하다.**

브라우저는 raw TCP 소켓을 열 수 없다. Sedona SOX(5001), Modbus TCP(502),
BACnet/IP(47808) — 어느 것도 브라우저가 직접 붙지 못한다.
"장비 쪽은 TCP, 화면 쪽은 WebSocket"인 중계 프로세스가 구조적으로 필수다.

```
[장비] --TCP--> [브리지] --WebSocket--> [브라우저 화면]
                   │
                   └─ 구독 관리 / 변경분만 push / 재연결
```

구현: `tools/point_bridge.py` (표준 라이브러리만, 의존성 없음)

```bash
python3 tools/point_bridge.py --port 8765              # 모의 드라이버
python3 tools/point_bridge.py --driver sox --device 192.168.1.50
```

화면 연결:

```
prototype/hmi-authoring-poc.html?ws=ws://localhost:8765
```

`?ws=` 가 없으면 종전처럼 모의 데이터로 돌고, 붙이면 실 데이터로 전환된다.
작화 작업과 실 연동이 같은 파일에서 이어진다.

### 변경분 전송 효과

6초 · 주기 0.4초 · 구독 9개 = 이론상 최대 135개 전송 기준:

| 데드밴드 | 실제 전송 | 비율 |
|---|---|---|
| 0.05 (기본) | 63개 | 47% |
| 3.0 | 10개 | 7% |

모의 데이터는 매 틱 난수로 흔들리는 최악 조건이다. 실제 BAS 데이터는
대부분의 포인트가 대부분의 틱에서 그대로이므로 절감폭은 이보다 훨씬 크다.

## 설계에서 중요한 네 가지

**① 구독 기반 — 전체 폴링 금지**
화면이 실제로 쓰는 태그만 등록한다. 포인트 수백 개짜리 현장에서 전체를
매 틱 보내면 곧 한계가 온다.

**② 변경분만 전송**
값이 안 바뀐 포인트는 보내지 않는다. 부동소수는 데드밴드를 둬서
의미 없는 미세 변화를 걸러낸다.

**③ 화면 전환 시 구독 교체 (누적 아님)**
가장 흔한 사고 지점이다. 구독이 계속 쌓이면 몇 시간 뒤 브리지가 죽는다.
`syncSubscription()` 은 화면이 바뀔 때마다 구독을 **교체**하며,
같은 구독을 반복 전송하지 않도록 이전 키와 비교한다.

**④ 재연결은 기본 기능이다**
현장에서 브리지 재기동·망 순단은 일상이다. 지수 백오프(1s→15s)로
재연결하고, 끊긴 동안에는 값을 흐리게 표시해 **오래된 값을 현재 값처럼
보여주지 않는다.** 이건 안전 문제다 — 멈춘 화면을 정상으로 오인하면
현장에서 위험하다.

### SOX 드라이버가 미완성인 이유

추측으로 채우면 현장에서 조용히 틀린 값을 표시하게 된다. 완성하려면
실제 장비에서 다음을 확인해야 한다.

- **프레이밍** — 버전에 따라 바이너리(dasp) 또는 XML. 이 프로젝트 문서는
  XML로 되어 있으나 장비에서 직접 확인이 필요하다
- **주소 매핑** — 컴포넌트/슬롯 주소 ↔ 태그 이름 규칙
- **인증·세션 유지** 절차
- **변경 통지(subscribe) 지원 여부** — 없으면 폴링으로 가야 하고,
  그러면 주기와 포인트 수의 상한이 달라진다

포트는 **5001**을 쓴다. 80은 장치 웹서버 전용이므로 쓰지 않는다.

드라이버 인터페이스(`connect / points / read / write`)는 이미 분리돼 있어,
프로토콜이 SOX든 Modbus든 BACnet이든 **브리지 본체는 그대로 두고 드라이버만
갈아끼우면 된다.** 위 네 가지가 확인되면 SOX 드라이버는 작은 작업이다.

## 남은 것

- 실제 EasyIO 장비 대상 SOX 드라이버 완성 및 현장 검증
- 쓰기(제어) 경로의 권한·확인 절차 — 현재 `write` 는 모의 드라이버에서만 동작
- TLS 및 인증. 현재 브리지는 인증이 없다. 폐쇄망 전제이며, 그렇지 않다면
  운영 투입 전 반드시 추가해야 한다
- 다중 장비·다중 브리지 구성에서의 태그 네임스페이스 정리
